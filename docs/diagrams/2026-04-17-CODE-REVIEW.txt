  CZĘŚĆ 2 -- BŁĘDY LOGICZNE I ANTI-PATTERNS
═══════════════════════════════════════════════════════════════════

  [BUG-1] ItemBrowser.SetItem(restored) na Start -- SPAWN W POWIETRZU
  ─────────────────────────────────────────────────────────────────
  ItemBrowser.cs:90-95
    Start() {
      LoadItems();
      int saved = PlayerPrefs.GetInt(PrefsKey, 0);
      SetItem(Mathf.Clamp(saved, 0, MaxItem));  // <-- spawn natychmiast
    }
  SetItem -> SpawnPreview używa head.position. Gracz może być w
  powietrzu (Y=42). Wtedy item spawnuje też w powietrzu.
  FIX: defer SetItem(restored) do grounded LUB do menu open.

  [BUG-2] AvatarGallery.Update -- POLLUJE GameObject.Find CO FRAME
  ─────────────────────────────────────────────────────────────────
  AvatarGallery.cs:117-141
    Update() {
      if (_spawned) return;
      if (!IsPlayerGrounded()) return;  // -> GameObject.Find each frame
    }
  GameObject.Find iteruje całą scenę. Wykonywane co frame przed
  pierwszym spawn -- może to być setki frames przy spadaniu.
  FIX: cache rig reference w Awake / przy pierwszym znalezieniu.

  [BUG-3] LocomotionController.Awake -- standHeight NADPISANY przez CC
  ─────────────────────────────────────────────────────────────────
  LocomotionController.cs:113-114
    _cc = GetComponent<CharacterController>();
    if (_cc != null) standHeight = _cc.height;  // <-- field overwritten
  Inspector value standHeight=1.8 jest IGNOROWANY -- używa CC.height.
  Inverted dependency: CC powinien być derived from standHeight.
  FIX: _cc.height = standHeight; (set CC from inspector value)

  [BUG-4] PlayerAvatar.Start vs AvatarGallery.Start -- RACE CONDITION
  ─────────────────────────────────────────────────────────────────
  AvatarGallery.Start defers spawn to Update.
  PlayerAvatar.Start runs SetAvatarMode immediately.
  Jeśli execution order PlayerAvatar przed Gallery, MaxMode może być
  niepoprawny (Gallery.Count=0 bo _instances null).
  Aktualnie OK bo Gallery.TryLoadRegistry tworzy _instances tablicę
  na Start (przed deferred spawn). Ale ZALEŻNE od execution order.
  FIX: explicit DefaultExecutionOrder na Gallery (-50).

  [BUG-5] LocomotionController.Update -- LATAŁ + MENU = stale velocity
  ─────────────────────────────────────────────────────────────────
  LocomotionController.cs:156-181
    Update() {
      if (!GameState.CanMove) return;  // <-- early exit
      ...
      if (_flyState == FlyState.Grounded) ApplyGravity();
      ApplyMove(horizontalMove);
    }
  Scenariusz: gracz LATA, otwiera menu. Update zwraca early.
  _verticalVelocity zostaje (np. +5 m/s ascending). Gracz wisi.
  Po Resume gracz dalej leci w górę z 5 m/s -- pozornie OK ale
  stick nie był puszczony, gracz może być zdezorientowany.
  Niski priorytet.

  [BUG-6] AvatarGallery + PlayerAvatar -- NormalizeToHeight DUPLICATED
  ─────────────────────────────────────────────────────────────────
  AvatarGallery.cs:279-290 + PlayerAvatar.cs:237-256
  Identyczna metoda w obu klasach. DRY violation.
  FIX: extract do AvatarUtils.NormalizeToHeight static helper.

  [BUG-7] PlagaGrabbable.Update -- nie sprawdza GameState
  ─────────────────────────────────────────────────────────────────
  PlagaGrabbable.cs:44-89
  Update() polluje OVRInput nawet w pauzie. Trzymając grip w menu,
  haptic dalej buzz. Może to OK (intencja "fizyczny grip"), ale
  zarówno trigger haptic odpala się w menu -- nie chcemy.
  FIX: if (!GameState.CanInteract) { StopGripHaptic; return; }

  [BUG-8] ItemBrowser.SetItem -- ZAWSZE despawn + respawn
  ─────────────────────────────────────────────────────────────────
  ItemBrowser.cs:126-145
    SetItem(index) {
      DespawnPreview();  // <-- ZAWSZE
      _selectedIndex = index;
      ...
    }
  Jeśli gracz wybiera ten sam item, item znika i pojawia się.
  FIX: if (index == _selectedIndex) return;

  [BUG-9] AvatarGallery._spawned -- DUPLICATED STATE
  ─────────────────────────────────────────────────────────────────
  bool _spawned + GameObject[] _instances. Mogą być out of sync.
  FIX: spawn check via _instances.Any(x => x != null).

  CZĘŚĆ 3 -- ZŁAMANIA SOLID
═══════════════════════════════════════════════════════════════════

  [SOLID-S1] PlayerAvatar -- 4 odpowiedzialności
  ─────────────────────────────────────────────────────────────────
  Single Responsibility VIOLATION:
    1. Stan avatara (mode, instance, animator)
    2. Spawn/despawn avatara
    3. Zarządzanie gallery preview state (DeactivateGalleryPreviews,
       SyncGalleryActiveIndex)
    4. Bone hiding (LateUpdate, head/neck scale)
  FIX: split na PlayerAvatarState, AvatarSpawner, AvatarBoneHider.

  [SOLID-S2] AvatarGallery -- 3 odpowiedzialności
  ─────────────────────────────────────────────────────────────────
  1. Loading registry
  2. Spawning preview row
  3. Tracking active index (UI state)
  FIX: split na RegistryLoader, GalleryRowSpawner, GalleryActiveSelector.

  [SOLID-S3] LocomotionController -- 4 odpowiedzialności
  ─────────────────────────────────────────────────────────────────
  448 linii. Robi:
    1. Movement (ApplyMove, CalculateHeadRelativeMovement)
    2. Fly state machine (UpdateFly, EndFlight)
    3. Stance state machine (UpdateStance, SetStance, LerpStance)
    4. Gravity
  FIX: split na 4 klasy z LocomotionController jako orchestrator.

  [SOLID-O1] PlagaGrabber -- modyfikacja base'a
  ─────────────────────────────────────────────────────────────────
  Open/Closed VIOLATION:
    grabEnd = -1f w Awake -- zmiana zachowania base klasy
  Hack na SDK które nie jest open for extension.
  Nie do naprawy bez modyfikacji SDK.

  [SOLID-L1] PlagaGrabber.GrabBegin -- LISKOV
  ─────────────────────────────────────────────────────────────────
  Liskov Substitution VIOLATION:
    base.GrabBegin() oczekuje że chwyci obiekt
    PlagaGrabber.GrabBegin() czasem wywołuje GrabEnd (releasuje)
  Nie krytyczne (SDK nie wywołuje GrabBegin externally) ale dziwne.

  [SOLID-D1] GameObject.Find używane wszędzie -- DIP
  ─────────────────────────────────────────────────────────────────
  Dependency Inversion VIOLATION:
    AvatarGallery, ItemBrowser, ObjectSpawner, PlayerAvatar
    wszystkie zależą KONKRETNIE od GameObject o nazwie "OVRCameraRig".
  FIX: wstrzyknij IPlayerRig interface (test, swap, mock).

  [SOLID-S4] GameState -- public static event leak risk
  ─────────────────────────────────────────────────────────────────
  Statyczny event = persistuje między scenami. Subskrybenci ze
  starej sceny zostają zawieszeni jeśli nie unsubscribe w OnDestroy.
  FIX: subskrybenci muszą OnDestroy -= OnStateChanged. Lub użyć
  ScriptableObject jako event bus.
